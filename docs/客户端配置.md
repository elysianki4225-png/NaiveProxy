# 客户端配置指南

本篇给出所有主流客户端的配置方法。安装完成后，你的脚本输出里已经包含这些信息，
也可以随时用 `sudo bash naiveproxy-install.sh info` 重新打印，或直接从
`/etc/caddy/naiveproxy/client/` 目录取文件（仅 root 可读）。

## 0. 先确认服务端正常

```bash
sudo bash naiveproxy-install.sh status
```

需要满足：

- `systemctl` 显示 `active (running)`；
- 「当前证书」一行显示的是 **Let's Encrypt / ZeroSSL** 等公开 CA 的证书（不是 `Caddy Local Authority`）；
- 客户端能 ping/连通服务器的 443 端口（`telnet 域名 443` 或 `curl -v https://域名` 正常返回）。

## 1. 需要填写的字段（所有客户端通用）

| 字段 | 值 | 备注 |
| --- | --- | --- |
| 服务器地址 / Server | **你的域名**（不是 IP！） | 例如 `abc123.203.0.113.10.nip.io` 或 `proxy.example.com` |
| 端口 / Port | 安装时设定的 HTTPS 端口（默认 **443**） | |
| 用户名 / Username | 安装时生成（`naiveproxy-install.sh info` 可查） | |
| 密码 / Password | 安装时生成 | |
| TLS / SNI | **与域名相同**，必须开启 TLS | 这是 NaiveProxy 的核心 |
| 传输协议 | HTTP/2（默认）或 HTTP/3（QUIC） | 两种可分别尝试 |

## 2. 官方 naive 客户端（推荐：Windows / Linux / macOS）

官方客户端使用 Chromium 网络栈，伪装效果与 Chrome 完全一致，**安全性与抗探测能力最好**。

### 2.1 下载

<https://github.com/klzgrad/naiveproxy/releases/latest> —— 文件名形如
`naiveproxy-v1xx.x.x-x-linux-x64.zip` / `naiveproxy-v1xx.x.x-x-win-x64.zip` / `...-macos-...`。

解压后得到 `naive`（Windows 为 `naive.exe`）。

### 2.2 配置方式一：config.json（推荐）

在 `naive` 同目录新建 `config.json`（内容就是安装脚本输出的【1】）：

```json
{
  "listen": "socks://127.0.0.1:1080",
  "proxy": "https://用户名:密码@你的域名:443"
}
```

然后双击/运行 `naive`（或 `naive.exe`），本机即出现 `127.0.0.1:1080` 的 **SOCKS5 + HTTP** 代理。

HTTP/3（QUIC）版本只需把 `https://` 改成 `quic://`：

```json
{
  "listen": "socks://127.0.0.1:1080",
  "proxy": "quic://用户名:密码@你的域名:443"
}
```

### 2.3 配置方式二：命令行参数

```bash
# HTTP/2
naive --listen=socks://127.0.0.1:1080 --proxy=https://用户名:密码@你的域名:443

# HTTP/3
naive --listen=socks://127.0.0.1:1080 --proxy=quic://用户名:密码@你的域名:443

# 同时开 SOCKS5(1080) 与 HTTP 代理(1081)，并允许局域网设备共用
naive --listen=socks://0.0.0.0:1080 --listen=http://0.0.0.0:1081 \
      --proxy=https://用户名:密码@你的域名:443
```

常用附加参数（详见 `naive --help` 或上游 USAGE.txt）：

| 参数 | 用途 |
| --- | --- |
| `--insecure-concurrency=2` | 网络质量差时增加隧道并发（会略微削弱抗流量分析能力，建议 ≤ 4） |
| `--tunnel-timeout=600` | CGNAT / 长连接卡死时定期重建隧道（会断开长连接型协议，如 SSH） |
| `--log=./naive.log` | 输出日志，用于排错 |
| `--no-post-quantum` | 关闭后量子密钥协商（一般无需使用） |

### 2.4 让系统/浏览器走代理

- **Windows**：Windows 设置 → 网络和 Internet → 代理 → 手动设置代理 `127.0.0.1:1080`
  （或使用 `naive.exe` 同目录下 `--listen=http://127.0.0.1:1080` 配合浏览器代理插件）；
- **macOS**：系统设置 → 网络 → 详情 → 代理 → SOCKS 代理 `127.0.0.1:1080`；
- **Linux**：桌面环境网络设置里填 SOCKS `127.0.0.1:1080`，或设置环境变量：
  ```bash
  export http_proxy=socks5h://127.0.0.1:1080 https_proxy=socks5h://127.0.0.1:1080 all_proxy=socks5h://127.0.0.1:1080
  ```

> 💡 多数浏览器（Firefox 等）可直接填 SOCKS5；Chrome/Edge 建议搭配 SwitchyOmega 之类的扩展，
> DNS 请设为「通过代理解析」，避免 DNS 泄漏。

## 3. Android

### 3.1 Exclave（官方推荐）

官方仓库 <https://github.com/dyhkwong/Exclave>。安装后：

1. 新建配置 → 选择 **Naive**（built-in）；
2. 依次填写：服务器 = 域名、端口 = 443、用户名、密码，TLS 开启（SNI 同域名）；
3. 或直接粘贴**分享链接**导入：
   ```
   naive+https://用户名:密码@域名:443#备注
   naive+quic://用户名:密码@域名:443#备注
   ```

### 3.2 Husi

<https://github.com/xchacha20-poly1305/husi> → 左下 `+` → 手动输入 → 类型选 **Naive**，
或「从剪贴板导入」分享链接。

### 3.3 NekoBox for Android

<https://github.com/MatsuriDayo/NekoBoxForAndroid>（需安装 `naive-plugin`）：

1. 左上菜单 → 分组 → 新建分组 → 类型「订阅」，把 **Base64 订阅内容**（安装输出的
   `subscribe-base64.txt`）或分享链接粘进去；
2. 或手动创建节点：类型 `Naive`，填写域名/端口/用户名/密码，TLS 打开。

> 注意：Android 上 `naive-plugin` 是独立 APK，NekoBox 会提示安装。

## 4. Windows：v2rayN

<https://github.com/2dust/v2rayN>（v6/v7 内置 naive 支持）：

1. 「服务器」→「从剪贴板导入批量URL」，粘贴
   `naive+https://用户名:密码@域名:443#备注`；
2. 或「添加 NaiveProxy 服务器」，手动填写域名、端口、用户名、密码并**勾选 TLS**；
3. 保存后设为活动服务器，开启「系统代理」（建议模式：自动配置系统代理 + 全局/规则）。

## 5. sing-box（全平台）

要求 **≥ 1.13.0**，并且使用包含 `libcronet` 的构建版本
（Linux：无后缀或 `-glibc`/`-musl`；Windows：官方包已带 `libcronet.dll`）。

出站配置（安装脚本输出的 `sing-box-outbound-h2.json` / `-h3.json`）：

```json
{
  "type": "naive",
  "tag": "naive-out",
  "server": "你的域名",
  "server_port": 443,
  "username": "用户名",
  "password": "密码",
  "quic": false,
  "tls": { "enabled": true, "server_name": "你的域名" }
}
```

- `"quic": true` + `"quic_congestion_control": "bbr"` 可改用 HTTP/3；
- 完整最小可用配置示例：

```json
{
  "log": { "level": "warn" },
  "inbounds": [
    { "type": "mixed", "tag": "mixed-in", "listen": "127.0.0.1", "listen_port": 2080 }
  ],
  "outbounds": [
    {
      "type": "naive",
      "tag": "naive-out",
      "server": "你的域名",
      "server_port": 443,
      "username": "用户名",
      "password": "密码",
      "tls": { "enabled": true, "server_name": "你的域名" }
    },
    { "type": "direct", "tag": "direct" }
  ],
  "route": { "final": "naive-out" }
}
```

运行：`sing-box run -c config.json`；或订阅方式导入 `subscribe-base64.txt` 的内容。

## 6. 分享链接与二维码

安装结果中的三种链接形式（客户端支持情况见括号）：

| 形式 | 示例 | 支持方 |
| --- | --- | --- |
| `naive+https://` | `naive+https://u:p@host:443#tag` | NekoBox / Husi / Exclave / v2rayN / sing-box（导入解析） |
| `naive+quic://` | `naive+quic://u:p@host:443#tag` | 同上（HTTP/3） |
| `https://` / `quic://` | `https://u:p@host:443` | **官方 naive 客户端**的 `config.json` / `--proxy=` |

- **Base64 订阅**：`subscribe-base64.txt` 就是上面 `naive+https://` 链接的 Base64 编码；
  可直接粘贴到支持 Base64 订阅的客户端（NekoBox、sing-box 等），也可放到你自己的静态服务器上作为订阅地址。
- **二维码**：服务器上安装 `qrencode` 后，脚本会额外生成 `qr-h2.png` / `qr-h3.png`：
  ```bash
  sudo apt-get install -y qrencode
  sudo bash naiveproxy-install.sh info   # 重新生成（若客户端目录已存在，可先 .info 直接查看）
  ```
  用手机扫码导入 `naive+https://` 链接（NekoBox/Husi/Exclave 支持扫码导入）。

## 7. 不支持的客户端（避免踩坑）

| 客户端 | 情况 |
| --- | --- |
| Clash / mihomo (Clash Meta) | 没有 naive 出站实现，**无法使用**（其配置模型里没有该协议）。请改用上表客户端。 |
| Shadowsocks/SSR 类客户端 | 协议不同，不能通用。 |
| 任何「只填 IP」的客户端 | 必须填域名 + 开启 TLS，否则既连不上也不安全。 |

## 8. 客户端排错速查

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 连接超时 / 一直转圈 | 安全组未放行 443；服务未运行 | 放行 443/tcp（h3 再放 443/udp）；`systemctl status caddy` |
| `certificate verify failed` / `SSL error` | 证书未签发成功，或客户端 SNI 填错 | `sudo bash naiveproxy-install.sh status` 看证书；SNI 必须等于域名 |
| `407 Proxy Authentication Required` | 用户名/密码错误 | 从 `info` 重新复制，注意用户名与密码之间是 `:` |
| HTTP/2 可用但 HTTP/3 不通 | 网络屏蔽 UDP 443（或被 QoS） | 客户端改回 `https://`（HTTP/2）；或服务端 `--http3 h2only` |
| 能连上但速度很慢 | 线路问题 / 拥塞控制 | 服务端启用 BBR（安装时选择 yes）、客户端尝试 quic；参见运维文档性能调优 |
| 用浏览器能开，Android 上不行 | 缺少插件或未开启 TLS | 安装 `naive-plugin`；确认节点 TLS 已勾选 |
| 只有部分网站打不开 | 服务端 ACL 或目标站点限制 | 默认禁止代理访问内网；如目标站点封锁机房 IP，则属正常现象 |
