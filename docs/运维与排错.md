# 运维与排错

本篇覆盖日常运维（服务管理、日志、配置变更、备份迁移、升级、卸载）、
性能调优（BBR、QUIC、连接池）、以及一张按现象定位问题的排错表。

---

## 1. 服务管理

```bash
systemctl status caddy            # 运行状态
systemctl restart caddy           # 重启（配置大改后用）
systemctl reload  caddy           # 优雅重载（推荐，不断开现有连接）
systemctl stop caddy              # 停止
systemctl start caddy             # 启动
systemctl enable caddy            # 开机自启（安装脚本已自动设置）
systemctl disable caddy           # 取消开机自启
systemctl cat caddy               # 查看当前生效的 unit 内容
```

脚本封装：

```bash
sudo bash naiveproxy-install.sh status     # 状态 + 证书签发者/到期时间
sudo bash naiveproxy-install.sh restart    # 重启并等待 HTTPS 就绪
sudo bash naiveproxy-install.sh info       # 打印节点信息
sudo bash naiveproxy-install.sh menu       # 交互式管理面板
sudo bash naiveproxy-install.sh log -f     # 实时日志
```

## 2. 日志与诊断

```bash
journalctl -u caddy -f                              # 实时日志
journalctl -u caddy -n 200 --no-pager               # 最近 200 行
journalctl -u caddy --since "10 min ago"            # 最近 10 分钟

# 配置校验（改完 Caddyfile 必做）
sudo caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile

# 把 Caddyfile 转成 JSON 看实际生效的配置（排错神器）
sudo caddy adapt --config /etc/caddy/Caddyfile --adapter caddyfile | less

# 二进制信息
caddy version
caddy list-modules | grep forward_proxy            # 应出现 http.handlers.forward_proxy
caddy build-info | grep -i forwardproxy            # 确认来自 klzgrad/forwardproxy 分支
```

> 🔒 **隐私提醒**：Caddy 默认**不写访问日志**，脚本也没有开启，因此服务器上不会留下你访问过的网站记录。
> 但 HTTP 层的错误日志（如目标站点连接失败）会以 ERROR 级别写入 journald，其中可能包含目标域名。
> 如果你对此敏感，可以在日后的维护中参考 Caddy 官方文档，在全局块用 `log` 选项的 `include`/`exclude`
> 子选项排除 `http.log.error`，或直接限制 journald 的留存大小。

## 3. 修改配置的正确姿势

```bash
sudo cp /etc/caddy/Caddyfile /root/Caddyfile.$(date +%F)      # 1) 备份
sudo nano /etc/caddy/Caddyfile                                # 2) 编辑
sudo caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile   # 3) 校验
sudo systemctl reload caddy                                   # 4) 热重载
sudo systemctl status caddy                                   # 5) 确认
```

常见改动示例：

```caddyfile
# ① 换伪装目标网站（把探测流量反代到别的站点）
reverse_proxy https://www.example.org {
    header_up Host {upstream_hostport}
}

# ② 关闭 HTTP/3（在全局块中加入）
servers :443 {
    protocols h1 h2
}

# ③ 增加第二个可用账号（可多次写 basic_auth）
forward_proxy {
    basic_auth user1 pass1
    basic_auth user2 pass2
    ...
}

# ④ 允许代理访问内网（默认禁止；确认风险后再改）
acl {
    allow all
}
```

> 💡 **换伪装（反代）目标推荐用子命令**（自动备份 + 校验 + 热重载，不断开连接）：
> ```bash
> sudo bash naiveproxy-install.sh masq --masq-target www.example.org   # 直接写域名即可
> sudo bash naiveproxy-install.sh masq                                 # 交互式选择（反代/静态页/不伪装）
> sudo bash naiveproxy-install.sh masq --masq static --webroot /var/www/naiveproxy
> ```
> 也可以用安装命令整体覆盖：`sudo bash naiveproxy-install.sh install --masq-target https://example.org --force`
> （会重新生成配置并重启服务；原 Caddyfile 自动备份为 `Caddyfile.bak.<时间戳>`）。

## 4. 性能调优

### 4.1 服务端

| 项目 | 做法 |
| --- | --- |
| **加速模块（默认已启用）** | 安装时自动应用，包含 BBR+fq、按内存自适应的收发缓冲（8/16/32/64 MB）、TCP Fast Open、`tcp_notsent_lowat`、`tcp_slow_start_after_idle=0`、MTU 探测、keepalive 收紧、队列增大、`udp_*_min` 抬高 |
| 档位 | `standard`（默认）/ `aggressive`（内存 ≥1.5G 时缓冲翻倍到 64MB）/ `off`；切换：`accel apply --profile aggressive` |
| 连接池 | Caddyfile 中 `max_idle_conns` / `max_idle_conns_per_host` **随档位自动放大**（off=128/8、standard=256/16、aggressive=512/32） |
| 文件描述符 | unit 已设 `LimitNOFILE=1048576`，无需改动 |
| QUIC 拥塞控制 | 预编译包（x86_64）内置 **sing-quic BBRv1 补丁**，HTTP/3 场景比默认 Cubic 更快；源码编译的版本不含该补丁 |
| 端口跳跃/QoS | 若运营商对 443/UDP 限速，改用 `--http3 h2only` 只走 TCP |

```bash
# 加速模块状态（档位 / 拥塞控制 / 缓冲上限 / 连接复用 / 本机内存）
sudo bash naiveproxy-install.sh accel

# 原始内核视角
sysctl net.ipv4.tcp_congestion_control net.core.default_qdisc net.core.rmem_max net.core.wmem_max
ss -ti | head -20          # 看 bbr 与 cwnd
```

> 完整参数表、内存自适应策略、关闭/回滚方法与 FAQ 见 **[加速与性能.md](加速与性能.md)**。

### 4.2 客户端

| 参数 | 场景 |
| --- | --- |
| `quic://` 替换 `https://` | 丢包严重 / 高延迟线路，QUIC 通常更快 |
| `--insecure-concurrency=2` | 网络抖严重导致隧道频繁重建时（会降低抗流量分析能力，建议 ≤ 4） |
| `--tunnel-timeout=600` | CGNAT、NAT 超时导致的卡死（注意会断开 SSH 这类长连接） |
| DNS | 客户端开启「通过代理解析 DNS」，避免 DNS 泄漏影响体验与安全 |

## 5. 备份与迁移

需要备份的内容：

```bash
sudo tar czf naiveproxy-backup-$(date +%F).tar.gz \
  /etc/caddy \
  /var/lib/caddy \
  /etc/systemd/system/caddy.service \
  /etc/sysctl.d/99-naiveproxy.conf
```

- `/etc/caddy/naiveproxy/site.env` + `client/`：账号、域名与客户端配置；
- `/var/lib/caddy/.local/share/caddy/certificates`：已签发证书（**迁移后可直接复用**，避免重新申请；
  但 **ACME 账户私钥**也在这个目录里，它是敏感数据，请妥善保管）。

迁移到新服务器：

```bash
# 新机先安装一份（配置随意），再覆盖回来
sudo bash naiveproxy-install.sh install --yes
sudo systemctl stop caddy
sudo tar xzf naiveproxy-backup-YYYY-MM-DD.tar.gz -C /
sudo chown -R caddy:caddy /var/lib/caddy
sudo systemctl start caddy
sudo bash naiveproxy-install.sh status
```

> ⚠️ 迁移后请确认新机器的公网 IP 与域名解析一致（nip.io 域名里嵌了 IP，换 IP 必须换域名）。

## 6. 升级

```bash
# 方式 1：脚本升级（重新走预编译/在线构建/源码编译三种降级路径，保留配置与证书）
sudo bash naiveproxy-install.sh update

# 方式 2：手动替换二进制
sudo systemctl stop caddy
sudo curl -fL -o /usr/local/bin/caddy \
  https://github.com/klzgrad/forwardproxy/releases/latest/download/caddy-forwardproxy-naive.tar.xz  # 见下方说明
sudo systemctl start caddy
```

> 预编译包是 `.tar.xz` 压缩包，正确做法是：
> ```bash
> sudo install -m0755 ./caddy-forwardproxy-naive/caddy /usr/local/bin/caddy
> caddy version && caddy list-modules | grep forward_proxy
> ```

**建议**：不要盲目追新。上游 `klzgrad/forwardproxy` 的 tag 形如 `v2.11.7-naive`，
`CADDY_VERSION` 文件为 `v2.11.7`（即客户端 Chromium 栈对应的 Caddy 版本）。升级前先备份。

## 7. 卸载

```bash
# 交互式卸载（可选择只停服务或彻底删除）
sudo bash naiveproxy-install.sh uninstall

# 彻底删除（非交互）
sudo bash naiveproxy-install.sh uninstall --yes
```

卸载过程会自动做这些清理：

- 停止并禁用 `caddy` 服务、删除 `/etc/systemd/system/caddy.service`
- 删除 `/etc/caddy`（含 Caddyfile、证书数据）、`/var/lib/caddy`、`/var/www/naiveproxy`
- **加速模块**：删除 `/etc/sysctl.d/99-naiveproxy-accel.conf`，并把拥塞控制/排队规则恢复成安装前的值
- 可选删除 `/usr/local/bin/caddy` 与系统用户 `caddy`

手工清理（如需完全恢复系统）：

```bash
sudo systemctl stop caddy && sudo systemctl disable caddy
sudo rm -f /etc/systemd/system/caddy.service && sudo systemctl daemon-reload
sudo rm -rf /etc/caddy /var/lib/caddy /var/www/naiveproxy /usr/local/bin/caddy
# 加速模块参数（并把拥塞控制恢复成 cubic，或你原来的值）
sudo rm -f /etc/sysctl.d/99-naiveproxy-accel.conf
sudo sysctl -w net.ipv4.tcp_congestion_control=cubic net.core.default_qdisc=fq_codel
sudo rm -f /etc/sysctl.d/99-naiveproxy.conf && sudo sysctl --system
sudo userdel caddy 2>/dev/null; sudo groupdel caddy 2>/dev/null
```

## 8. 排错表（按现象定位）

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| `systemctl status caddy` 是 `failed` | Caddyfile 语法错误 / 端口被占用 | `journalctl -u caddy -n 50` 看报错；`caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile` |
| 日志出现 `listen tcp :443: bind: address already in use` | 443 被 Nginx/Apache/其它进程占用 | `ss -lntp \| grep :443` 找到进程并停用，或改端口 `--https-port 8443` |
| 日志出现 `unrecognized directive: forward_proxy` | 装的是官方 Caddy（缺少插件） | 重装：`sudo bash naiveproxy-install.sh install --force`（或用官方下载页/`xcaddy` 手动编译） |
| `too many certificates already issued` | Let's Encrypt 限速 | 换 ZeroSSL：`install --ca zerossl --email 你@邮箱 --force`；详见《证书与CA》 |
| 状态里证书签发者是 `Caddy Local Authority` | ACME 尚未成功（Caddy 用内部证书临时提供 TLS） | 按《证书与CA》第 8 节逐项排查；`journalctl -u caddy \| grep -i acme` |
| 客户端连不上，服务器本地正常 | 云安全组 / 防火墙未放行 | 放行 443/tcp（h3 另需 443/udp）；`--firewall yes` 可让脚本处理系统防火墙 |
| 客户端报 407 | 账号密码错 | `sudo bash naiveproxy-install.sh info` 重新核对 |
| 浏览器能访问站点但显示 502 | 反代目标站点服务器访问不了 | 换伪装目标：`masq --masq-target 能访问的站点`，或 `masq --masq static` |
| 提示「N 项内核参数未生效」 | 受限容器（LXC/OpenVZ/面板 KVM）不允许改 | 重启后再看；长期不生效可 `accel off`（不影响可用性） |
| 加速模块想彻底关掉 | — | `sudo bash naiveproxy-install.sh accel off`（删除参数文件并恢复原拥塞控制/排队规则） |
| 想换回原来的拥塞控制算法 | — | `accel off` 会恢复安装前记录的值；也可 `sysctl -w net.ipv4.tcp_congestion_control=cubic` |
| 访问站点显示证书警告 | 用了 staging / 自签证书 | 重新申请正式证书 |
| HTTP/3 客户端超时 | UDP 443 被阻断 / 被 QoS | 客户端改 HTTP/2；或服务端 `--http3 h2only` |
| 速度慢、延迟高 | 线路 & 拥塞控制 | 确认加速模块已生效（`accel`），必要时切 `aggressive`；客户端试 `quic://`；更换线路更好的机房 |
| 流量跑满/异常高 | 被当成公开代理滥用 | 立刻更换密码（重装 `--force` 会自动生成新密码），并检查 ACL 是否被放开 |
| `caddy reload` 报 admin 不可用 | 服务未运行 / admin 端口被改 | `systemctl restart caddy` 后再 reload |
| 脚本提示 `无法自动获取公网 IPv4` | 服务器出网受限 | 用 `--ip <你的公网IP>` 指定 |

### 一键收集诊断信息（排错时贴给他人看）

```bash
{
  echo "== os =="; cat /etc/os-release | head -3
  echo "== caddy =="; /usr/local/bin/caddy version; /usr/local/bin/caddy list-modules | grep forward_proxy
  echo "== service =="; systemctl status caddy --no-pager -n 20
  echo "== ports =="; ss -lntup | grep -E ':(80|443)\b'
  echo "== cert =="; echo | openssl s_client -connect 127.0.0.1:443 -servername "$(grep -oP '^:\d+, \K[^ ]+' /etc/caddy/Caddyfile | head -1)" 2>/dev/null | openssl x509 -noout -issuer -dates
  echo "== log =="; journalctl -u caddy -n 50 --no-pager
} > /tmp/naive-diagnose.txt 2>&1; echo "已生成 /tmp/naive-diagnose.txt"
```

> ⚠️ 分享诊断信息前，请先删除其中的域名、密码等信息（`/etc/caddy/Caddyfile` 含密码，不要直接外发）。

## 9. 安全建议

1. **不要**把 `--allow-private` 打开，除非你完全清楚「代理被用来访问内网」的后果；
2. 定期更换代理密码（重装 `--force` 即可，会保留域名与证书配置结构）；
3. Caddy 的 admin API 默认只监听 `127.0.0.1:2019`，**不要**把它暴露到公网；
4. 系统层面常规加固：SSH 禁用密码登录（改用密钥）、设置 `fail2ban`、及时打安全补丁；
5. 不要在公共场合（聊天群、截图、论坛）分享含密码的节点信息与二维码；
6. 只与信任的人共享节点，滥用会导致 IP 被墙或服务器被封停。
